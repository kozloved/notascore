## How Fast meter is chosen

Fast does **not** use `MeterEstimator` for the written score.

1. `BeatTracker.track_stable()` runs madmom DBN with `beats_per_bar=[3, 4]`.
2. madmom can emit only **3/4 or 4/4** (`madmom_beats.py`: `time_signature = "3/4" if beats_per_bar == 3 else "4/4"`).
3. That string is passed as `ScoreMeta.time_sig_hint`.
4. `NotationPlanner._resolve_meter()` **prefers the hint** over `MeterEstimator`.

`MeterEstimator` still runs and is stored as `debug.selected_meter`, which is
why debug JSON can say `4/4` while the plan is `3/4`.

MIDI ingest skips beat tracking and uses the file time-signature, so MIDI
stays 21/21 with NotationPlan and F1 1.00.

## Gate calibration applied

Meter categories now live on each catalog case as `meter_eval` and are written into corpus `expected.meter_eval`.

`evaluate.py` flags `meter_mismatch` only for `STRICT_METER`, **including Fast mode**. Hands / voices remain MIDI-only gates.

| meter_eval | Cases |
|---|---|
| STRICT_METER | midi_3_4, midi_6_8, compound_6_8, waltz_3_4, plus other long unambiguous 4/4 (scales, quarters, eighths, two-hand scale, block chords, …) |
| METER_AMBIGUOUS | triplets, syncopation, midi_rh_lh_tracks, octave_doubling |
| METER_NOT_EVALUATED | sixteenths, dotted |

Expected effect:

- MIDI ingest: still 21/21 (meters already correct; new hand gate already 1.00).
- Fast: **FAIL** `midi_6_8`, `compound_6_8`, `waltz_3_4` with `meter_mismatch`. That is the honest gate. Other Fast meter mistakes (triplets, syncopation, short clips) no longer hide behind “Fast ignores meter”; they are explicitly not enforced.

## Top systemic failure

**Madmom beat/downbeat tracking is the Fast meter authority and cannot express 6/8, while NotationPlanner trusts that hint over a better `MeterEstimator`.**

1. **User impact.** Fast scores of compound meter and many 3/4 clips come out as 3/4 or 4/4 with the wrong barline. Measure sums still pass, so the XML looks “valid” while every bar is the wrong length class. Players see waltz as 4/4 and 6/8 as 3/4.
2. **Frequency.** 2/2 required 6/8 Fast cases and 1/2 required 3/4 Fast cases (waltz) are wrong. midi_3_4 happens to pass. Several short 4/4 clips also flip to 3/4 but are now `METER_AMBIGUOUS`.
3. **Downstream damage.** Wrong meter poisons quantization grids, rest filling, and any later voice/hand metric that uses measure boundaries. F1 is a separate Basic Pitch problem and does not cause these meter errors (MIDI F1 is 1.00 with the same planner).
4. **Implementation complexity.** Medium, localized: either (a) add 6/8 (compound) to the DBN search / map 3-beat compound pulse to 6/8, (b) stop treating madmom 3/4 as a hard hint when `MeterEstimator` ranks 6/8 clearly higher, or (c) both. Do **not** start with a global estimator rewrite; the estimator already ranks 6/8 first on the reference 6/8 cases (0.91 and 0.93 vs 3/4 0.43).

Secondary systemic issue (not gated yet): Basic Pitch `min_ms=127.7` plus sine-tone fixtures drop 16ths, dotted pickups, inner chord tones, and octave doubles. That is transcription, not the cleaner. MIDI ingest remains the structure gate.

No production algorithm was changed in this checkpoint.
